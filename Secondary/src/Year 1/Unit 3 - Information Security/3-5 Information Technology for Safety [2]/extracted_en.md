What is a Digital Signature?

Proving Data Source and Integrity

### Digital Signature and the Hash Function

A digital signature is a technology that uses public key encryption and hash values to prove that the transmitted data is from the sender and has not been tampered with — click each term:

Hash function

A function that calculates a unique value based on the input data.

💡 It is impossible to restore the original data from the hash value.

Hash value

The value generated by the hash function — a unique fingerprint of the data.

💡 If even one character in the data changes, the hash value changes completely.

Digital signature

A technology that uses public key encryption and hash values to prove the data is from the sender and unaltered.

💡 Like a personal digital seal — proving the message came from you.

How Is a Digital Signature Created?

Sender and Recipient Procedures

### The Sender's Procedure

### Step 1 — Generate the hash value

Use a hash function to generate a hash value from the plaintext to be sent.

### Step 2 — Encrypt the hash value

Encrypt the hash value using the sender's private key — this encrypted hash is called the digital signature.

### Step 3 — Send

Send both the plaintext and the digital signature to the recipient.

### The Recipient's Procedure

### Step 4 — Decrypt with the public key

Use the sender's public key to decrypt the received digital signature and retrieve the original hash value.

### Step 5 — Generate a new hash

Use the same hash function used in step 1 to generate a new hash value from the received plaintext.

### Step 6 — Compare

Compare the two hash values from steps 4 and 5. If they match, it proves the message is from the sender and has not been tampered with.

### ⚠️ Common Mistakes

Confusing the signature keys — encryption uses the sender's private key, decryption uses the sender's public key (not the private one!).

Forgetting the comparison step — without matching the two hash values, there is no proof the message was not tampered with.

Certification Authority and Digital Certificates

A Trusted Third Party

### What is a Certification Authority (CA)?

Click the cards to understand the CA's role:

Certification Authority (CA)

A trusted third-party organization that verifies whether a public key truly belongs to its claimed owner.

💡 Without it, anyone could claim your public key is theirs!

Digital certificate

Issued by the CA — it includes the public key and identifying information of the key owner.

💡 The certificate guarantees the public key truly belongs to the named person.

### ⚠️ Common Mistakes

Thinking a digital signature alone is enough — no, without a CA and digital certificate, someone could impersonate the sender.

Confusing a digital certificate and a digital signature — the certificate holds the public key, the signature proves the message is from the sender and unaltered.

SSL / TLS

Encrypting Browser–Server Communication

### What is SSL/TLS?

Click the card to understand how SSL/TLS works:

SSL/TLS

A technology used to encrypt communication between a web server and a web browser — it uses the session key method in this encryption.

💡 The URL of an encrypted web page begins with https:// — SSL was the original and TLS is the more secure version that took its name.

### ⚠️ Common Mistakes

Thinking http:// means encryption — no, encryption appears in https:// (the S means Secure).

Confusing SSL and TLS — TLS was introduced as a more secure version of SSL, and the two terms are used together as SSL/TLS.
